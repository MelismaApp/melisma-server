Better Lyrics Server

Where lyrics come from

Every enabled source is asked at once, and the answers are merged rather than raced — one source supplies the timing, the rest lend translations, readings, background vocals and credits. Order only breaks ties. A source with a missing token is skipped rather than queried.

Test every source
Runs a real lookup for Blinding Lights by The Weeknd through every enabled source — the same code path a request from the app takes. The per-source Test above only proves a credential is accepted, which is not the same thing: a token can be accepted and then refused the lyrics.

Apple Music

Two tokens, and a subscription only gets you one of them. This is the reason the server exists: these cannot safely live inside the app.

Developer token (bearer)
No Apple Developer membership needed — use the web player's own. Open music.apple.com, open DevTools → Network, click any song, find a request to amp-api.music.apple.com, and copy the whole Authorization: Bearer eyJ… value. It is shared by every web listener and lasts months, but it does expire — the badge above says when.
Media user token
This is the one your subscription gets you. On music.apple.com, signed in: DevTools → Application → Cookies → media-user-token. It dies with the browser session, so if lyrics start returning 403 this is what to replace.

Keeping them alive

A Spotify web token lasts about an hour and cannot be renewed by asking — Spotify closed that endpoint. Only a browser loading the player can mint one, so this server carries a Chromium and does it itself on a schedule. Paste an sp_dc cookie below and there is nothing else to configure.

Automatic refresh checking…
A cookie rather than a password on purpose: sp_dc still authenticates the player, so nothing here stores a password and there is no login form for two-factor auth or a CAPTCHA to interrupt. It lasts about a year — paste a new one when it stops working.

BL_TOKEN_REFRESH_COMMAND overrides this with an external command whose stdout is JSON of token name to value, for renewing something the built-in harvest does not know about. It comes from the environment and cannot be set from this page — an admin session should not get to choose what the host executes.

Everything else

All optional. Each source that has no token stays quiet rather than failing.

Spotify web token
Copied out of the web player: open.spotify.com → DevTools → Network → any request to api-partner.spotify.com → the Authorization: Bearer … value. It lasts about an hour, which is what the refresh above is for. The cookie route below is closed — Spotify now refuses to trade a cookie for a token.
Spotify sp_dc cookie
From a signed-in session at open.spotify.com: DevTools → Application → Cookies → sp_dc. This is what the automatic refresh above uses — with it set, the hour-long web token renews itself and you never paste one again. Lasts about a year.
Spotify application
A client id and secret from developer.spotify.com/dashboard — tick Web API only, and any redirect URI will do since this grant never uses one. This is what makes the ISRC reliable: api.spotify.com rate-limits a web-player token so hard that the ISRC and cover art mostly never arrive, while an application token has proper quotas.

It does not replace the cookie above. Lyrics are not in the public API at all, and the audio analysis was closed to applications registered after November 2024 — both still come from the player's own token.
Musixmatch user token
Optional. The server mints an anonymous one on demand; your own reaches more of the catalogue.
NetEase cookie
Optional. Raises the per-IP limits and unlocks some regional catalogues.

Library

Every song the server has been asked about, and everything it holds on each — the merged lyrics, every provider's raw response, and the artwork, palette, tempo and analysis the tokens turned up. Ordered by artist and title by default.

Let the local network look lyrics up without the key
On, because the app sends no authentication and a phone on the same Wi-Fi is the normal case. It only ever applies to lyric lookups — the admin page and the tokens always need the key. Turn it off if anything public proxies to this server: the check reads the connecting socket, and a proxy on this host looks local whoever is really behind it.
